# Telegram AI Study Assistant

**Technical specification · v0.2 · November 19, 2026 · Working draft**

## 1. MVP goals and scope

A single user launches the Telegram Mini App from a private chat with the bot and interacts with Claude Opus as they would in a familiar chat application. The user can maintain several independent conversations, return to any of them after closing the app, pick up the conversation, open attachments, and request changes to a previous calculation.

The MVP accepts study questions on any subject without requiring the user to select a discipline first. Claude on the web with code execution and file creation enabled serves as the functional benchmark. The comparison starts with regular chat, attachment analysis, and downloadable results. In Telegram, the main interaction happens through free-form messages. The user clarifies, revises, approves, and continues work in the conversation. When a task requires computation, the model uses Python. If the available data or execution environment prevents progress, the app explains the specific limitation or asks for the missing information.

The MVP targets one user, one model, one application server, and one way to run Python. The agreed model and concurrency limits apply. The list of features to verify is set before implementation. Any new Claude features introduced after that agreement are considered separately.

### 1.1. Scenarios for comparison with Claude on the web

| Capability | Behavior to verify in the Mini App |
|---|---|
| Regular chat | Responses stream as they are generated. The user can create, find in history, rename, reopen, and delete a conversation. Messages and files are available on return. |
| Input documents and images | A request can use multiple attachments. Initial testing covers text-based PDFs, scans, images, DOCX, CSV, TSV, TXT, and XLSX. Compare the full format list with the web app and agree on it before development. |
| Large PDF analysis | The chat uses text, tables, and visual information from the selected pages. When the whole document exceeds the model's limits, the user can continue with a page range. |
| Multi-stage tasks | Opus shows a plan and starts the first stage immediately if it has enough information. The user clarifies, corrects, or approves interim results through regular messages. Opus proceeds after approval in the conversation. |
| Creating and revising files | Verify downloadable XLSX, DOCX, PDF, PPTX, and charts. When the user requests an Excel workbook with working formulas, changing an input must recalculate dependent results. A revision creates a new file version in the same chat. |
| Web search | The MVP supports requests for current information and returns clickable source links. |
| English practice in chat | The MVP includes topic-based language exercises generated by Opus. Multiple-choice quizzes appear as interactive blocks in the conversation. |
| Advanced capabilities | Defer Projects, memory across chats, Research, and connectors until a use case is confirmed. Further work on Artifacts is planned for a later phase (section 4.3). |

These scenarios describe the result the user should see. The libraries and sandbox capabilities available through the Claude API may differ from those in the web app, so acceptance testing uses the intended user's real files and assignments. Keep the input files, prompt, and expected outcome for key scenarios. Verify Anthropic's built-in tools for XLSX, DOCX, PDF, and PPTX in the first technical prototype. ## 2. Model and tools

| Setting | Decision |
|---|---|
| Provider | Anthropic Messages API |
| Model ID | `claude-opus-5-5` |
| Reasoning effort | `output_config.effort = "high"` for MVP requests |
| Model configuration | One server-side setting. Model selection in the UI is deferred until after the MVP. |
| Responses | Stream available text and tool activity statuses. |
| Computation | Anthropic Code Execution in a managed sandbox |
| Web search | The `web_search` tool in the Anthropic Messages API. Show source links returned by the provider. |

The server explicitly sends `high` because Opus 5.5 defaults to `medium`. The API key stays on the application server. Track API usage per request and associate it with the conversation and the message that triggered it. [Effort configuration](https://platform.claude.com/docs/en/build-with-claude/effort) · [Opus 5.5](https://platform.claude.com/docs/en/models/opus-5-5/overview)

The Code Execution environment includes NumPy, SciPy, pandas, statsmodels, SymPy, and openpyxl, among other libraries. Each container has 1 CPU, 5 GiB of RAM, and 5 GiB of working space. The sandbox can create files. The app downloads and retains generated files so it can serve them after the calculation finishes and the container expires. [Code Execution](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool)

Use web search when the user requests it or the answer requires current information. Store source links with the answer so they remain available when the user reopens the chat. If search is unavailable, show an error and let the user retry. Agree on the per-message search call limit along with the API budget. [Web Search in the Claude API](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)

### 2.1. API budget and owner notifications

The owner can set and change the project's spending threshold in USD per calendar month. In the MVP, the owner uses a command in a private Telegram chat with the bot. For example, `/budget 50` sets a USD 50 threshold and `/budget` shows the active threshold and spending for the current month. The backend verifies the owner's Telegram user ID and accepts positive amounts only. The setting is stored in PostgreSQL and takes effect immediately. The app tracks spending from the start and enables alerts once the owner sets a threshold.

Calendar month boundaries use the Europe/Prague time zone by default. The backend updates estimated project costs after receiving usage data. It includes billable tokens, caching, web search, and billable code execution to the extent that the provider returns enough data to estimate those charges. Rates are set in configuration.

The first time spending exceeds the active threshold in a given month, the bot sends an alert to the owner's private Telegram chat. When the owner sets a threshold, the backend immediately compares it with spending to date. The notification includes estimated spending, the threshold, and the billing period. The application continues processing requests. PostgreSQL stores notification state so that later calculations, threshold changes, and server restarts respect an alert already sent for that month. The backend retries after temporary delivery failures.

Alerts use a separately configured Telegram chat ID for the owner. The owner starts the bot once to enable notifications. Mini App access still depends on the authorized user. Alerts contain only spending and billing details, with conversation and file contents excluded.

Label the spending figure in the notification as an estimate. Use Anthropic's report for the project workspace to reconcile actual spending. [Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)

## 3. Dedicated VPS

**Proposed starting configuration: 2 vCPUs, 4 GiB RAM, and 40 GiB SSD/NVMe storage.** This is an estimate for one user, cloud-based computation, and bounded uploads. Validate it using the intended user's typical PDFs and XLSX files. The application runs without a GPU.

| VPS component | Purpose |
|---|---|
| HTTPS and Mini App | UI, file uploads, and result downloads |
| Python backend and Telegram bot | Sign-in, access checks, history, Anthropic calls, and response streaming |
| PostgreSQL | Conversations, messages, run statuses, file metadata, and API usage records |
| Persistent file volume | Attachments and results that must stay available when the user returns to a conversation |

Model-generated code runs in Anthropic Code Execution, within the sandbox's resource limits. VPS sizing depends primarily on the application, database, file sizes, and concurrent uploads. Stream uploads directly to disk and enforce size limits.

The initial 40 GiB disk covers the operating system, containers, database, files, and logs. The provisional quota for source and result files is 10 GiB. Account for temporary free space needed for container updates and backups when selecting a hosting plan.

The proposed deployment uses Docker Compose on one Linux VPS. The application server handles calculations as background jobs tied to the originating conversation. Closing the Mini App or switching chats leaves the job running.

### 3.1. File uploads and storage

| MVP limit | Value |
|---|---|
| Size per file | 80 MiB initially, about 14% above a 70 MiB file |
| Combined attachment size per message | 100 MiB. For example, an 80 MiB PDF and a 20 MiB Excel workbook. |
| Message text size | Proposed separate limit of 64 KiB in UTF-8 |
| Retention of input and output files | Until the conversation is deleted, subject to the overall disk quota |

The total attachment limit applies to attached files. Message text has its own limit. The Mini App uploads files directly to the backend, which enforces limits during upload and when the message is sent. When the user reaches the disk quota, the app explains the issue and lets them free space by deleting old conversations.

Large PDFs are passed to Anthropic through the Files API using a `file_id`. The Mini App's upload limit is measured in bytes. Model processing is also subject to Anthropic's page, format, and context limits. If the full document exceeds those limits, the app offers page-range selection and keeps the original PDF in the conversation. [PDF support in the Claude API](https://platform.claude.com/docs/en/build-with-claude/pdf-support)

### 3.2. Concurrent runs

The MVP allows one active computation per user. While it runs, the user can read other chats and compose drafts. If the user tries to start another computation, the interface shows that the execution slot is occupied.

Associate state, status updates, and response streams with the conversation and the individual run ID. The backend enforces the run limit as a separate rule. The UI and storage model track statuses independently by conversation so concurrent runs across chats can be enabled later.

A stage awaiting approval releases the execution slot. The user can start a run in another conversation and return to approve the earlier stage later.

## 4. Conversations and context

- One responsive Mini App works in both mobile and desktop Telegram. Both provide access to the same conversations, history, attachments, results, and interactive quizzes.
- The Mini App opens the last conversation. The user can open the recent conversations list or start a new chat in one action from the chat screen.
- Each conversation stores messages, attachments, and results. The user can run several related calculations and return to them later.
- The backend associates Opus calls and results with a `conversation_id`. Each call receives context assembled from the selected conversation.
- The response streams to the originating chat. When reopened, the app loads the saved state.
- Access to the UI and its data is granted to one Telegram user ID verified by the server.

### 4.1. English practice and quizzes

The user stays in the regular chat and can request a grammar or vocabulary quiz, fill-in-the-blank exercises, or feedback on their own sentences. They can specify the topic, level, and number of questions in the request. Grading and explanations stay in the same conversation, so the user can ask why an answer is incorrect or request extra practice on a weak topic.

Multiple-choice quizzes appear as interactive blocks in the conversation. The user selects options and sees how many questions they have answered. Selections persist when the Mini App is reopened. The user can request grading with a regular message such as “Check my answers” and receive a score and an explanation of mistakes. Answers remain editable until grading.

Opus returns structured questions, options, correct answers, and explanations. The backend validates the structure and stores the answer key. The UI receives the questions and options, then receives the results after grading. The backend saves selections and calculates the score without additional Opus requests. For open-ended exercises, the user writes an answer in chat and Opus checks it in context.

Quiz and attempt history is available in the conversation. A separate study dashboard, a course plan, and overall English progress statistics are candidates for after the MVP.

### 4.2. Solving complex tasks in stages

For a multi-stage task, Opus first presents a short plan describing what each stage will produce and starts the first stage immediately if it has enough information. If it needs more information to begin, it asks a clarifying question. The first approval comes after Opus presents the result of the first stage. The user can also explicitly request a staged approach. An ordinary question can be answered in one response.

1. Opus completes the current stage and presents the result in chat. This can include clarified inputs, an interim calculation, a chart, or a file.
2. The user can send one or more clarifications as regular messages. They apply to the current stage, and the revised result appears in the chat.
3. The user approves the result through a message such as “Yes, that's right. Continue.” Opus interprets intent from context. A correction keeps the task at the current stage. If a message is ambiguous, Opus asks whether to continue. The backend starts the next stage using the approved version of the result. Duplicate delivery of the same message creates just one run.
4. The next stage receives the approved data, assumptions, and relevant artifacts from earlier stages. At the final stage the user receives the result and can request revisions before closing out the task.

The conversation stores the plan, current stage number, stage state, and versions of interim results. On reopening the Mini App, the user can see whether the stage is running or awaiting approval and which revisions were applied. If an instructor specified a method, the plan reflects it. When required information is missing, Opus asks a clarifying question at the current stage.

### 4.3. Result previews and revisions through chat

In the MVP, the user can open a PDF, chart, or results table from an Excel workbook directly in the conversation. On wide screens, the result appears beside the chat. On narrow screens, it opens on a separate screen with a route back to the same conversation. The XLSX preview displays the results table with calculated values and a chart if one was created. The complete workbook with formulas is available for download.

When the user sends a follow-up such as “Exclude 2022,” the backend associates the message with the open result and its version. After a successful recalculation, the preview updates to the new version. The previous version remains available in history. On failure, the user can still open the last successful version and read an explanation in chat.

The post-MVP goal is functional parity with Claude Artifacts. Each artifact has a stable identifier within its conversation, a content type, and version history. Each version links to its file and preview. The UI selects a viewer based on content type. This contract supports adding direct document and spreadsheet editing and isolated execution of interactive content later. Define the exact list of parity features when planning that phase.

## 5. Acceptance criteria for the first end-to-end scenario

1. The user launches the Mini App from Telegram and creates two conversations.
2. In the first chat, the user uploads a PDF and an XLSX file and requests a multi-stage calculation. Opus shows a plan and automatically starts the first stage. While it runs, the user opens the second chat's history and drafts a request. Attempting to start another calculation shows that the execution slot is occupied.
3. After receiving the first stage's result, the user sends two revisions as separate messages. Opus applies both to the same stage. The user closes the Mini App and returns to the latest result. The next stage is still awaiting approval.
4. The user writes “That's right now. Continue.” The next stage uses the corrected data. Duplicate delivery of the message creates just one run. Once all stages are complete, an XLSX file opens from the first chat and the second chat retains its own context.
5. Use an assignment with a known answer to verify input interpretation, methodology, and numerical results. For acceptance of the general-purpose MVP, add several types of tasks, including one that required no task-specific UI or processing setup.
6. Test uploading a PDF of about 70 MiB alongside an XLSX file within the combined limit. A successful upload keeps both files in the chat. Exceeding the per-file or combined attachment limit yields a distinct, understandable error for each case.
7. Compare at least three file-based assignments previously completed in Claude on the web. Cover reading a table or formula from a scan, calculating from multiple inputs and generating an XLSX file, and revising a previously generated file after a clarification. When the output requires formulas, verify that changing an input value recalculates the results.
8. For a request for current information that explicitly calls for an internet search, Opus searches the web. The answer includes clickable source links, which remain available when the user reopens the chat.
9. The user requests an English quiz and selects answers in the interactive block. They close the app after answering several questions, return to the same chat, and continue with their saved answers. They request grading through a message and receive a score and explanations. They can ask a follow-up about a specific mistake in chat.
10. The owner sets and changes the budget through a private chat with the bot. The change takes effect immediately. A command from a different Telegram user ID is rejected. With test data, spending exceeds the active threshold. The owner receives an alert and the app continues accepting requests. Later usage updates and a backend restart leave that month's alert count at one. Exceeding the threshold the following month triggers a new alert.
11. In both mobile and desktop Telegram, the user launches the Mini App, switches conversations, uploads a PDF, downloads an XLSX result, and continues a quiz with saved answers. On mobile, the input field and send action remain accessible with the keyboard open.
12. Open a result and ask to “Exclude 2022.” Verify that the preview and downloaded file show the same version and final values. If recalculation fails, verify that the previous version still opens. On mobile, verify that the user can return from the preview to the same conversation.
